# JavaVerse Risk Register

| Risk ID    | Category                  | Description                                                                                                                              | Severity | Likelihood | Mitigation Strategy                                                                                                                                                     | Owner / Phase | Status    |
| :--------- | :------------------------ | :--------------------------------------------------------------------------------------------------------------------------------------- | :------- | :--------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :-------- |
| **RSK-01** | Security / Sandbox        | Container-runner execution engine candidate may fail performance, security, or resource isolation requirements.                          | High     | Medium     | Enforce `SANDBOX_PROVIDER=mock` until the Phase 6 sandbox feasibility spike passes. Maintain fallback to isolated Judge0 architecture.                                  | Phase 6       | Active    |
| **RSK-02** | Security / AI             | Unvalidated AI models or real API execution in early phases could cause unintentional egress, cost, or non-deterministic test flakiness. | High     | Low        | Enforce `AI_PROVIDER_PRIMARY=mock` at runtime via fail-fast Zod validation through Phase 4. Real adapters (Anthropic/Gemini) deferred to Phase 5.                       | Phases 1–4    | Mitigated |
| **RSK-03** | Data Integrity            | Race conditions during user registration or role update could create multiple active OWNER accounts.                                     | High     | Low        | Enforced in PostgreSQL DDL via partial unique index `idx_users_single_active_owner` (`WHERE role = 'OWNER' AND status = 'ACTIVE'`). Verified in clean DB tests.         | Phase 1       | Mitigated |
| **RSK-04** | Security / Secrets        | Credentials, database passwords, or session tokens committed to Git repository.                                                          | Critical | Low        | Pinned Gitleaks scanner (`v8.30.1`), configured `.gitleaks.toml`, strictly ignored `.env*` files in `.gitignore`, and restricted generated file permissions to 0600.    | Phase 1       | Mitigated |
| **RSK-05** | Supply Chain              | Transitive npm vulnerabilities in dependency tree.                                                                                       | High     | Medium     | Pinned `pnpm-lock.yaml`, configured `pnpm-workspace.yaml` overrides (`deepmerge-ts`), audited with `pnpm audit` and official `osv-scanner` (v2.7.0).                    | Continuous    | Mitigated |
| **RSK-06** | Infrastructure            | Redis queue memory exhaustion under high job load.                                                                                       | Medium   | Low        | `redis-queue` instance isolated from cache, configured with `appendonly yes` and `maxmemory-policy noeviction`. Dedicated cache instance configured with `allkeys-lru`. | Phase 1       | Mitigated |
| **RSK-07** | Performance / Reliability | Liveness probes failing due to database degradation causing cascading container restart loops.                                           | High     | Low        | Decoupled process liveness (`/api/v1/health`, zero external I/O) from dependency readiness (`/api/v1/readiness`). Verified during simulated database outages.           | Phase 1       | Mitigated |
| **RSK-08** | Security / CSP            | Static route script hash desynchronization during Turbopack builds causing browser CSP execution blocks.                                 | High     | Low        | Automated post-build static hash extraction (`scripts/extract-static-hashes.mjs`) synchronizes verified hashes directly to `@javaverse/security` and `.env.local`.      | Phase 2       | Mitigated |
| **RSK-09** | Accessibility / Contrast  | Low-contrast text on brand amber or blue accents failing WCAG 2.2 AA (4.5:1 floor).                                                      | High     | Low        | Primary CTA uses dark ink on amber (8.2:1); links use `#b45309` (4.6:1) and `#0369a1` (7.3:1); verified across 15 routes via `@axe-core/playwright`.                    | Phase 2       | Mitigated |
| **RSK-10** | Security / Fixture Leak   | Development and visual review fixture states leaking diagnostic backdoors into production builds.                                        | High     | Low        | Fixture state harness (`dashboardData.ts`) strictly gated behind server-side `E2E_FIXTURES_ENABLED=true` check; completely inactive in production builds.               | Phase 2       | Mitigated |
