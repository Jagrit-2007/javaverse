# JavaVerse Risk Register

| Risk ID    | Category                        | Description                                                                                                                                                                                                           | Severity | Likelihood | Mitigation Strategy                                                                                                                                                                                                                                                                                                                                                                   | Owner / Phase  | Status    |
| :--------- | :------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------- | :--------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------- | :-------- |
| **RSK-01** | Security / Sandbox              | Container-runner execution engine candidate may fail performance, security, or resource isolation requirements.                                                                                                       | High     | Low        | Phase 6 feasibility spike passed with flying colors; container-runner verified against Adoptium Java 21 Alpine container with resource bounds; mock fallback available.                                                                                                                                                                                                               | Phase 6        | Mitigated |
| **RSK-02** | Security / AI                   | Unvalidated AI models or real API execution in early phases could cause unintentional egress, cost, or non-deterministic test flakiness.                                                                              | High     | Low        | Enforce `AI_PROVIDER_PRIMARY=mock` at runtime via fail-fast Zod validation through Phase 4. Real adapters (Anthropic/Gemini) deferred to Phase 5.                                                                                                                                                                                                                                     | Phases 1–4     | Mitigated |
| **RSK-03** | Data Integrity                  | Race conditions during user registration or role update could create multiple active OWNER accounts.                                                                                                                  | High     | Low        | Superseded and closed by Single-Account Model: the `role` column, `idx_users_single_active_owner` constraint, and OWNER concept have been permanently removed from PostgreSQL schema in migration `20261109210000_single_learner_account_model`.                                                                                                                                      | Single-Account | Closed    |
| **RSK-04** | Security / Secrets              | Credentials, database passwords, or session tokens committed to Git repository.                                                                                                                                       | Critical | Low        | Pinned Gitleaks scanner (`v8.30.1`), hardened `.gitleaks.toml` with exact file-specific allowlists (no broad test wildcards), strictly ignored `.env*` files in `.gitignore`.                                                                                                                                                                                                         | Phase 1        | Mitigated |
| **RSK-05** | Supply Chain                    | Transitive npm vulnerabilities in dependency tree.                                                                                                                                                                    | High     | Low        | Pinned `pnpm-lock.yaml`; removed `@lhci/cli` from workspace to eradicate all 5 High transitive findings; containerized Lighthouse audits via pinned `patrickhulce/lhci-client:0.15.1`; zero Critical/High findings in full audit or OSV-Scanner.                                                                                                                                      | Continuous     | Mitigated |
| **RSK-06** | Infrastructure                  | Redis queue memory exhaustion under high job load.                                                                                                                                                                    | Medium   | Low        | `redis-queue` instance isolated from cache, configured with `appendonly yes` and `maxmemory-policy noeviction`. Dedicated cache instance configured with `allkeys-lru`.                                                                                                                                                                                                               | Phase 1        | Mitigated |
| **RSK-07** | Performance / Reliability       | Liveness probes failing due to database degradation causing cascading container restart loops.                                                                                                                        | High     | Low        | Decoupled process liveness (`/api/v1/health`, zero external I/O) from dependency readiness (`/api/v1/readiness`). Verified during simulated database outages.                                                                                                                                                                                                                         | Phase 1        | Mitigated |
| **RSK-08** | Security / CSP                  | Static route script hash desynchronization during Turbopack builds causing browser CSP execution blocks.                                                                                                              | High     | Low        | Automated post-build static hash extraction (`scripts/extract-static-hashes.mjs`) synchronizes verified hashes directly to `@javaverse/security` and `.env.local`.                                                                                                                                                                                                                    | Phase 2        | Mitigated |
| **RSK-09** | Accessibility / Contrast        | Low-contrast text on brand amber or blue accents failing WCAG 2.2 AA (4.5:1 floor).                                                                                                                                   | High     | Low        | Primary CTA uses dark ink on amber (8.2:1); links use `#b45309` (4.6:1) and `#0369a1` (7.3:1); verified across 15 routes via `@axe-core/playwright`.                                                                                                                                                                                                                                  | Phase 2        | Mitigated |
| **RSK-10** | Security / Fixture Leak         | Development and visual review fixture states leaking diagnostic backdoors into production builds.                                                                                                                     | High     | Low        | Fixture state harness (`dashboardData.ts`) strictly gated behind server-side `E2E_FIXTURES_ENABLED=true` check; completely inactive in production builds.                                                                                                                                                                                                                             | Phase 2        | Mitigated |
| **RSK-11** | Security / Bootstrap Race       | Interrupted bootstrap or first-visitor race creating unauthorized OWNER account.                                                                                                                                      | Critical | Low        | Superseded and closed by Single-Account Model: bootstrap tokens, scripts, and routes completely deleted; product uses public local signup with 5-account limit.                                                                                                                                                                                                                       | Single-Account | Closed    |
| **RSK-12** | Data Integrity / Concurrency    | Parallel invitation creation exceeding deployment `MAX_USERS` seat limit.                                                                                                                                             | High     | Low        | Superseded and closed by Single-Account Model: invitations table, routes, and seat reservation logic completely deleted.                                                                                                                                                                                                                                                              | Single-Account | Closed    |
| **RSK-13** | Security / Session Fixation     | Session token theft or indefinite session extension via idle touch manipulation.                                                                                                                                      | High     | Low        | Dual-token architecture (HMAC digest in DB, raw cookie token), fixed 7-day absolute expiry unextended by touch, 24h idle timeout, reauth requirement for revocation.                                                                                                                                                                                                                  | Phase 3        | Mitigated |
| **RSK-14** | Reliability / Rate Limiting     | Ephemeral Redis cache outage allowing brute-force password or OTP attacks on sensitive auth endpoints.                                                                                                                | High     | Low        | Fail-closed rate limiting policy on sensitive authentication routes (`login`, `mfa_challenge`, `resend_verification`, `password_forgot`) during Redis outage.                                                                                                                                                                                                                         | Phase 3        | Mitigated |
| **RSK-15** | Performance / SSE Saturation    | SSE connection leaks or unbounded tabs exhausting worker process memory and connections.                                                                                                                              | Medium   | Low        | Strictly enforced per-user ceiling (max 3 concurrent SSE connections); returns HTTP 429 `SSE_CONNECTION_LIMIT_REACHED` on excess; heartbeats and dead connection cleanup every 15s.                                                                                                                                                                                                   | Phase 4        | Mitigated |
| **RSK-16** | Privacy / PII Ingestion         | Learners submitting prompts with personal names, API keys, or private filesystem paths into KB training candidates.                                                                                                   | High     | Low        | Multi-pattern regex PII scrubber filters emails, IPv4/IPv6, URLs, phone numbers, home directories, and secrets; requires explicit opt-in (`consentImprove: true`); immediate purge on consent withdrawal.                                                                                                                                                                             | Phase 10       | Mitigated |
| **RSK-17** | Security / Upload Quarantine    | Malicious files or executables uploaded via chat attachments.                                                                                                                                                         | High     | Low        | Magic byte header validation against allowed MIME types (PNG, JPEG, GIF, WebP, PDF); isolated object storage bucket; ClamAV antivirus quarantine pipeline.                                                                                                                                                                                                                            | Phase 5        | Mitigated |
| **RSK-18** | Data Integrity / Rewards        | Double-spending or race condition duplicating XP awards or badges on simultaneous submissions.                                                                                                                        | Medium   | Low        | Enforced via PostgreSQL composite unique constraint on `user_progress(user_id, item_type, item_id)` and atomic conditional updates; verified under 10 concurrent requests.                                                                                                                                                                                                            | Phase 11       | Mitigated |
| **RSK-19** | Disaster Recovery / Loss        | Catastrophic failure or database corruption causing unrecoverable loss of curriculum, user progress, or chat histories.                                                                                               | Critical | Low        | Automated compressed backup (`backup-db.sh`) and restore (`restore-db.sh`) with SHA-256 verification and automated end-to-end disaster recovery drill (`test:backup-restore`).                                                                                                                                                                                                        | Phase 11       | Mitigated |
| **RSK-20** | Security / AI Credentials       | Gemini API key leaked in proxy/server logs via URL query parameters.                                                                                                                                                  | Medium   | Low        | Transmit API key strictly via `x-goog-api-key` header; sanitize all outgoing error payloads to redact API key strings.                                                                                                                                                                                                                                                                | Remediation    | Mitigated |
| **RSK-21** | Performance / SSE Leak          | SSE connections remaining active and locking user connection limits after abrupt browser tab closure or network drop.                                                                                                 | Medium   | Low        | Bound `request.signal` abort handling directly to idempotent stream teardown; guarantees single-execution decrement of active connection counters.                                                                                                                                                                                                                                    | Remediation    | Mitigated |
| **RSK-22** | Security / Backup Leak          | Database backup dumps created with world-readable permissions (0644) under operator default umask.                                                                                                                    | Low      | Low        | Enforced `umask 077` and `chmod 600` on output files and checksums in `backup-db.sh`; verified with automated test under `umask 000`.                                                                                                                                                                                                                                                 | Remediation    | Mitigated |
| **RSK-23** | Data Integrity / Concurrency    | Race condition during concurrent local signups exceeding 5-account limit.                                                                                                                                             | High     | Low        | Transaction-scoped PostgreSQL advisory lock `pg_advisory_xact_lock(74619284)` serializes registration and counts active accounts; verified in integration tests with 5 concurrent signups.                                                                                                                                                                                            | Local Auth     | Mitigated |
| **RSK-24** | Security / Privilege Escal      | Legacy bootstrap endpoints or URLs used to create or elevate unprivileged accounts to OWNER.                                                                                                                          | Critical | Low        | Superseded and closed by Single-Account Model: bootstrap routes deleted, `role` column dropped; zero privilege escalation surfaces remain.                                                                                                                                                                                                                                            | Single-Account | Closed    |
| **RSK-25** | Disaster Recovery / Volumes     | Local database accounts and progress lost if Docker volumes are purged.                                                                                                                                               | High     | Low        | Local state persisted in named volume `postgres_data` across normal container restarts; documented operator warning that `docker compose down -v` permanently drops accounts.                                                                                                                                                                                                         | Local Auth     | Mitigated |
| **RSK-26** | Security / CSP Dev Hydration    | Static script hash CSP blocking dynamic Next.js HMR and inline scripts in development mode, preventing browser form hydration.                                                                                        | High     | Low        | Middleware applies dynamic nonce CSP in `NODE_ENV=development` while preserving strict static script hashes in `NODE_ENV=production`; verified in Chromium and Firefox.                                                                                                                                                                                                               | Local Auth     | Mitigated |
| **RSK-27** | Operations / Worker Dev Boot    | Worker package startup script invoking missing `src/index.js` instead of TypeScript source `src/index.ts`.                                                                                                            | Medium   | Low        | Converted `apps/worker` dev script to `tsx watch src/index.ts` with explicit `.env` file loading in `env.ts`; verified clean worker startup during `pnpm dev`.                                                                                                                                                                                                                        | Local Auth     | Mitigated |
| **RSK-28** | UX / Developer Tooling Leak     | Next.js DevTools overlay ("Route Info", "Clear Segment Overrides") appearing in development views.                                                                                                                    | Low      | Low        | Identified as Next.js 15 dev-mode Turbopack internal overlay (`next-devtools`); automatically stripped from production builds (`next build`); verified absence via automated E2E assertion.                                                                                                                                                                                           | Product Align  | Mitigated |
| **RSK-29** | Privacy / External AI Leak      | Learner prompts and source code sent to external AI providers without consent, or containing sensitive PII.                                                                                                           | High     | Low        | Pre-prompt local PII scrubbing enforced via `@javaverse/security`; visible AI status banner and external-AI consent modal implemented before transmission to Gemini or Anthropic.                                                                                                                                                                                                     | Product Align  | Mitigated |
| **RSK-30** | Data Loss / Volume Purge        | Operators running `docker compose down -v` accidentally wiping local account data.                                                                                                                                    | Medium   | Low        | Documented explicit warnings and persistence lifecycle contract in `start-dev.sh`; data preserved in named volume `javaverse_postgres_data` across stop/start cycles.                                                                                                                                                                                                                 | Product Align  | Mitigated |
| **RSK-31** | Data Isolation / Test Collision | Automated test suites (`test`, `test:clean-db`) running against shared local development database (`javaverse`) and deleting account rows via test lifecycle hooks, causing manual development accounts to disappear. | High     | Low        | Partitioned databases (`javaverse` for dev, `javaverse_test` for test suites, `javaverse_clean_verify` for clean DB tests, `javaverse_backup_verify_test` for DR drills); enforced central guard `assertSafeTestDatabase` with strict allowlist.                                                                                                                                      | Closure Audit  | Mitigated |
| **RSK-32** | Cost / Upstream AI Runaway      | Unchecked learner external AI requests or rapid repeated button clicks exhausting API quotas, incurring billing charges, or triggering upstream 429s.                                                                 | High     | Low        | Implemented Redis-backed daily per-user limit (`EXTERNAL_AI_DAILY_REQUEST_LIMIT_PER_USER=50`), installation-wide concurrency ceiling (`EXTERNAL_AI_MAX_CONCURRENCY=2`), and submit lock. Local Mock mode bypasses limits.                                                                                                                                                             | Closure Audit  | Mitigated |
| **RSK-33** | Safety / Destructive Test DB    | Automated tests accidentally running against production or dev database and deleting accounts or tables.                                                                                                              | Critical | Low        | Implemented central `assertSafeTestDatabase` in `@javaverse/db` parsing URL database name; strictly allowlists only `javaverse_test`, `javaverse_clean_verify`, `javaverse_backup_verify_test`; rejects `javaverse`, `postgres`, `production`.                                                                                                                                        | Data Safety    | Mitigated |
| **RSK-34** | Architecture / Single-Account   | Complex multi-role legacy (OWNER, MEMBER, invitations, bootstrap tokens, admin console) introducing privilege escalation vulnerabilities and administrative overhead for a local-first single-learner application.    | High     | Low        | Fully eradicated role concepts: dropped `users.role`, `invitations` table, `registration_mode`, `actor_role_at_time`, and PostgreSQL enums via forward-only migration `20261109210000_single_learner_account_model`. Converted legacy accounts to uniform learner state. Deleted obsolete admin/invitation/bootstrap routes and files. All accounts have uniform learner permissions. | Single-Account | Mitigated |
| **RSK-35** | UX / Accessibility              | Send Question button swapping label to "Processing..." causing test and accessibility locator failure during async job processing.                                                                                    | Medium   | Low        | Kept button mounted with permanent label "Send Question", communicating busy state via `aria-disabled="true"`, `aria-busy="true"`, and adjacent `role="status"` announcer.                                                                                                                                                                                                            | Ask-AI Audit   | Mitigated |
| **RSK-36** | Concurrency / Data Integrity    | Rapid double-clicks on Send Question triggering duplicate durable jobs and concurrent analysis runs for the same message.                                                                                             | High     | Low        | Enforced client-side synchronous submission lock and database-level PostgreSQL advisory lock `chat_post_<chatId>` checking for existing `PENDING`/`RUNNING` jobs; returns HTTP 409 Conflict.                                                                                                                                                                                          | Ask-AI Audit   | Mitigated |
| **RSK-37** | Auth / Sign-In Reliability      | Password leading/trailing whitespace causing hash mismatches on login; Playwright reusing running development server and mutating dev database.                                                                       | High     | Low        | Enforced strict password whitespace rejection during signup (`Password cannot begin or end with whitespace.`) in `@javaverse/schemas` and `@javaverse/security`; disabled `reuseExistingServer` in Playwright and enforced test database assertion before test execution; verified persistence across process and Docker restarts.                                                    | Sign-In Audit  | Mitigated |
