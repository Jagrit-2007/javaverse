# JavaVerse Risk Register

| Risk ID    | Category                     | Description                                                                                                                              | Severity | Likelihood | Mitigation Strategy                                                                                                                                                                                                                              | Owner / Phase | Status    |
| :--------- | :--------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------- | :------- | :--------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------ | :-------- |
| **RSK-01** | Security / Sandbox           | Container-runner execution engine candidate may fail performance, security, or resource isolation requirements.                          | High     | Low        | Phase 6 feasibility spike passed with flying colors; container-runner verified against Adoptium Java 21 Alpine container with resource bounds; mock fallback available.                                                                          | Phase 6       | Mitigated |
| **RSK-02** | Security / AI                | Unvalidated AI models or real API execution in early phases could cause unintentional egress, cost, or non-deterministic test flakiness. | High     | Low        | Enforce `AI_PROVIDER_PRIMARY=mock` at runtime via fail-fast Zod validation through Phase 4. Real adapters (Anthropic/Gemini) deferred to Phase 5.                                                                                                | Phases 1–4    | Mitigated |
| **RSK-03** | Data Integrity               | Race conditions during user registration or role update could create multiple active OWNER accounts.                                     | High     | Low        | Enforced in PostgreSQL DDL via partial unique index `idx_users_single_active_owner` (`WHERE role = 'OWNER' AND status = 'ACTIVE'`). Verified in clean DB tests.                                                                                  | Phase 1       | Mitigated |
| **RSK-04** | Security / Secrets           | Credentials, database passwords, or session tokens committed to Git repository.                                                          | Critical | Low        | Pinned Gitleaks scanner (`v8.30.1`), hardened `.gitleaks.toml` with exact file-specific allowlists (no broad test wildcards), strictly ignored `.env*` files in `.gitignore`.                                                                    | Phase 1       | Mitigated |
| **RSK-05** | Supply Chain                 | Transitive npm vulnerabilities in dependency tree.                                                                                       | High     | Low        | Pinned `pnpm-lock.yaml`; removed `@lhci/cli` from workspace to eradicate all 5 High transitive findings; containerized Lighthouse audits via pinned `patrickhulce/lhci-client:0.15.1`; zero Critical/High findings in full audit or OSV-Scanner. | Continuous    | Mitigated |
| **RSK-06** | Infrastructure               | Redis queue memory exhaustion under high job load.                                                                                       | Medium   | Low        | `redis-queue` instance isolated from cache, configured with `appendonly yes` and `maxmemory-policy noeviction`. Dedicated cache instance configured with `allkeys-lru`.                                                                          | Phase 1       | Mitigated |
| **RSK-07** | Performance / Reliability    | Liveness probes failing due to database degradation causing cascading container restart loops.                                           | High     | Low        | Decoupled process liveness (`/api/v1/health`, zero external I/O) from dependency readiness (`/api/v1/readiness`). Verified during simulated database outages.                                                                                    | Phase 1       | Mitigated |
| **RSK-08** | Security / CSP               | Static route script hash desynchronization during Turbopack builds causing browser CSP execution blocks.                                 | High     | Low        | Automated post-build static hash extraction (`scripts/extract-static-hashes.mjs`) synchronizes verified hashes directly to `@javaverse/security` and `.env.local`.                                                                               | Phase 2       | Mitigated |
| **RSK-09** | Accessibility / Contrast     | Low-contrast text on brand amber or blue accents failing WCAG 2.2 AA (4.5:1 floor).                                                      | High     | Low        | Primary CTA uses dark ink on amber (8.2:1); links use `#b45309` (4.6:1) and `#0369a1` (7.3:1); verified across 15 routes via `@axe-core/playwright`.                                                                                             | Phase 2       | Mitigated |
| **RSK-10** | Security / Fixture Leak      | Development and visual review fixture states leaking diagnostic backdoors into production builds.                                        | High     | Low        | Fixture state harness (`dashboardData.ts`) strictly gated behind server-side `E2E_FIXTURES_ENABLED=true` check; completely inactive in production builds.                                                                                        | Phase 2       | Mitigated |
| **RSK-11** | Security / Bootstrap Race    | Interrupted bootstrap or first-visitor race creating unauthorized OWNER account.                                                         | Critical | Low        | CLI-initiated bootstrap (`pnpm bootstrap:owner`), single-use 64-char token (15m TTL), encrypted ticket, mandatory TOTP proof before account row creation.                                                                                        | Phase 3       | Mitigated |
| **RSK-12** | Data Integrity / Concurrency | Parallel invitation creation exceeding deployment `MAX_USERS` seat limit.                                                                | High     | Low        | Transaction-scoped PostgreSQL advisory lock `pg_advisory_xact_lock(74619283)` in shared `invitations.ts` service serializing seat reservations; verified in live DB concurrency tests.                                                           | Phase 3       | Mitigated |
| **RSK-13** | Security / Session Fixation  | Session token theft or indefinite session extension via idle touch manipulation.                                                         | High     | Low        | Dual-token architecture (HMAC digest in DB, raw cookie token), fixed 7-day absolute expiry unextended by touch, 24h idle timeout, reauth requirement for revocation.                                                                             | Phase 3       | Mitigated |
| **RSK-14** | Reliability / Rate Limiting  | Ephemeral Redis cache outage allowing brute-force password or OTP attacks on sensitive auth endpoints.                                   | High     | Low        | Fail-closed rate limiting policy on sensitive authentication routes (`login`, `mfa_challenge`, `resend_verification`, `password_forgot`) during Redis outage.                                                                                    | Phase 3       | Mitigated |
| **RSK-15** | Performance / SSE Saturation | SSE connection leaks or unbounded tabs exhausting worker process memory and connections.                                                 | Medium   | Low        | Strictly enforced per-user ceiling (max 3 concurrent SSE connections); returns HTTP 429 `SSE_CONNECTION_LIMIT_REACHED` on excess; heartbeats and dead connection cleanup every 15s.                                                              | Phase 4       | Mitigated |
| **RSK-16** | Privacy / PII Ingestion      | Learners submitting prompts with personal names, API keys, or private filesystem paths into KB training candidates.                      | High     | Low        | Multi-pattern regex PII scrubber filters emails, IPv4/IPv6, URLs, phone numbers, home directories, and secrets; requires explicit opt-in (`consentImprove: true`); immediate purge on consent withdrawal.                                        | Phase 10      | Mitigated |
| **RSK-17** | Security / Upload Quarantine | Malicious files or executables uploaded via chat attachments.                                                                            | High     | Low        | Magic byte header validation against allowed MIME types (PNG, JPEG, GIF, WebP, PDF); isolated object storage bucket; ClamAV antivirus quarantine pipeline.                                                                                       | Phase 5       | Mitigated |
| **RSK-18** | Data Integrity / Rewards     | Double-spending or race condition duplicating XP awards or badges on simultaneous submissions.                                           | Medium   | Low        | Enforced via PostgreSQL composite unique constraint on `user_progress(user_id, item_type, item_id)` and atomic conditional updates; verified under 10 concurrent requests.                                                                       | Phase 11      | Mitigated |
| **RSK-19** | Disaster Recovery / Loss     | Catastrophic failure or database corruption causing unrecoverable loss of curriculum, user progress, or chat histories.                  | Critical | Low        | Automated compressed backup (`backup-db.sh`) and restore (`restore-db.sh`) with SHA-256 verification and automated end-to-end disaster recovery drill (`test:backup-restore`).                                                                   | Phase 11      | Mitigated |
